# Taiyo.AI Data‑Engineering Project

This project provides a complete, end‑to‑end implementation of the Taiyo.AI data‑engineering trial task.  It demonstrates how to discover official sources of infrastructure and construction projects in California, scrape and standardise the data, validate it against a defined schema, and set up an automated pipeline for continuous updates.  All code is written in Python 3 and can be run locally or deployed to a production environment.

## Directory structure

```
project/
│  README.md                – this document
│  requirements.txt         – Python dependencies
│  schema.json              – unified data schema with validation rules
│  sample_data.csv          – example dataset conforming to the schema
│
├─ scrapers/                – individual source scrapers
│   ├─ __init__.py
│   ├─ base.py              – common scraping utilities and data models
│   ├─ eureka.py            – scraper for the City of Eureka upcoming projects
│   ├─ richmond.py          – scraper for City of Richmond major projects
│   └─ ...                  – add additional city scrapers here
└─ pipeline.py              – entry point to run all scrapers, validate, and load data
```

## Getting started

1. **Install dependencies** – create a virtual environment and install the required libraries.

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. **Run the pipeline** – execute the pipeline script to scrape each source, validate the records and write to disk.  In a production deployment this script would run under cron or Airflow.

   ```bash
   python pipeline.py
   ```

   By default the script writes a `combined_projects.csv` file to the project root containing the aggregated data.

3. **Add new sources** – create a new Python module under `scrapers/` that implements a `scrape()` function returning a list of dictionaries matching the schema.  Import the scraper in `pipeline.py` and add it to the list of scrapers.

4. **Deploy to production** – containerise the application with Docker, configure environment variables for database connections, and schedule the `pipeline.py` script with cron or an orchestrator like Airflow.

## Schema

The unified schema used for all project data is defined in `schema.json`.  Each field includes a description and a simple validation rule.  The important fields mirror those specified in the trial task:

* `original_id` (string, unique) – identifier from the source system.
* `aug_id` (string, UUID) – autogenerated unique identifier.
* `country_name`, `country_code` – must be "United States" and "USA".
* `region_name`, `region_code` – world region names and codes; for US sources use "North America"/"NAC".
* `title`, `description`, `status`, `date` – core project metadata.
* `procurementMethod`, `budget`, `currency`, `buyer`, `sector`, `subsector` – optional procurement fields.
* `map_coordinates` – GeoJSON point if coordinates are available.
* `url` – the web page where the project was found.

The pipeline uses the `jsonschema` package to enforce these rules during validation.
